What it does

  1. 01Shows what you have

    One list of every skill, plugin and MCP server on your computer, with a mark for each agent that has it.

  2. 02Switches with one click

    Turn a skill on for one agent and off for another. Nothing is deleted, so you can turn it back on.

  3. 03Installs what you paste

    Paste any install command for a skill, an MCP server or a plugin, or a GitHub repository. It installs it for the agents you choose.

  4. 04Collections, whole or in part

    A publisher's set of skills comes as one folder. Get all of it or only the ones you tick, and save sets of your own.

  5. 05Works per project

    Give one project its own servers and skills, and edit its AGENTS.md or CLAUDE.md in place.

  6. 06Keeps skills current

    Check a skill against its GitHub repository and update it when a newer version is out. Or make a copy that is yours to change.

  7. 07Reads before it installs

    A skill from GitHub is scanned for risky instructions first, and you see what was found before you confirm.

  8. 08Backs up your skills

    Save the skills you keep to a GitHub repository you name, so a new computer starts with them.

Works with your agents It finds the ones on your computer. In Settings you can leave any of them out.

    Questions about the app

    Is the window on this page the real app?

    Yes. It is the same interface the desktop app shows, built from the same code, running in your browser on sample data. It cannot see or change anything on your computer; only the desktop app can.

    What does the desktop app change on my computer?

    Your agents' own settings files and skill folders, such as ~/.claude.json, ~/.cursor/mcp.json and ~/.claude/skills. It asks before it installs or deletes anything.

    What about tokens and API keys?

    They stay where they are. The app will not copy an MCP server that carries a key from one agent to another, and nothing from the catalog needs a secret.

    Does it install the agents themselves?

    No. It works on the agents you already have. An agent you install later shows up the next time the app looks.

    When can I download it?

    The Mac build is not published yet. Until it is, the catalog does the installing part today, with one line in your terminal.

    Questions, answered

    What does the line actually do?

    It finds the agents on your machine (or just the ones you chose with --to), registers each MCP server with every agent using that agent's own CLI where it has one (claude mcp add, codex mcp add, gemini mcp add, code --add-mcp) and merges JSON config for the rest (~/.cursor/mcp.json). Skills install through the open skills CLI, globally, into every agent you tool up.

    Does it install the agents themselves?

    No. Tool up! works on the agents you already have. Install them first (or grab them with Get'Em!), then run your line. Agents installed later get tooled up the next time you run it.

    Is it safe?

    The script is plain bash you can read before running it: hit “View script”, or add --dry-run to print every action without changing anything. Remote servers are just URLs; nothing is sent anywhere until you sign in to them from your agent. Skills are instructions your agent follows, so skim the ones you add.

    Where do tokens and API keys go?

    Never in the line, the share link or the script. Servers marked oauth open a sign-in the first time your agent uses them, and the agent keeps the credentials. Tool up! never sees them.

    Does re-running it duplicate things?

    No. Every step checks first: servers an agent already has are skipped and skills already on disk are left alone, so only what's missing is added. Add --update to re-install the skills you picked at their latest version.

    How do I remove something?

    Use the agent's own command: claude mcp remove sentry -s user, codex mcp remove sentry, gemini mcp remove -s user sentry. For Cursor and VS Code delete the entry from their mcp.json. Skills: npx skills remove -g tdd.

    How were the servers picked, and why isn't Postgres here?

    This is a short list on purpose, not a directory: official servers, from the tools' own makers, that a developer or a team would really use with an agent. Narrow or overlapping ones (one product's docs, one more web search) stay out. Every remote URL is called each week, so a server that stops answering drops out.

    Nothing here needs a secret. Servers that want an API key, a token or a connection string, like Postgres, MongoDB or Firecrawl, are not listed, because a secret must never end up in a command, a link or a script. Servers that sign you in with your browser (OAuth), like GitHub or Slack, are fine. For the others, add them yourself with your agent's own mcp add and keep the key in an environment variable.

    How were the skills picked?

    High signal over volume: the skills people actually install and keep, from the official repos of the tools they belong to and a few hand-picked community ones. Clones and look-alike forks are left out. Install counts refresh daily, and a check makes sure every skill still exists in its repo.

    Can I share my setup?

    Yes. “Copy link” encodes your selection in the URL, and anyone who opens it gets the same picks and the same line. “Download .sh” gives you a script with the picks baked in that works without this site.
